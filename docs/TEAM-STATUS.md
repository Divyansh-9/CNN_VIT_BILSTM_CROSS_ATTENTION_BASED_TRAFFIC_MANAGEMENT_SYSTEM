# Where the project stands (13 November 2026)

**The system is built and the experiments are done.** What is left is the final report and paper, plus a
few checks that need people, a real camera or a second computer. This page is the short version. The
detail is in [BUILD-LOG.md](../BUILD-LOG.md), the status board, and
[PRD-CHANGELOG.md](00-planning/PRD-CHANGELOG.md), the record of every decision and fix.

## What is built

| Part | What it does |
|---|---|
| **Counting** | YOLO counts vehicles per lane from a fixed camera, one frame every 2 s. The deployed edge reproduces the offline counts exactly on 10 clips (71,140 of 71,140 values) |
| **Forecasting** | For the next 60 s, per approach: a congestion class (LOW, MEDIUM, HIGH; the persistence forecaster) and an expected vehicle count (a ridge model) |
| **MFSTNet** | The CNN + ViT + BiLSTM vision model, with all eight ablation variants (A–H), evaluated leave-one-camera-out over 5 seeds |
| **Signal control (simulation)** | PPO on a SUMO intersection, against tuned Webster baselines |
| **The deployed system** | Edge node → MQTT → FastAPI server → React dashboard. It has both safety fallbacks; when the broker stops, the edge switches to its local cycle after exactly the 10 s timeout. Docker is verified in CI |
| **The dashboard and workbench** | One page for live forecasts, analysing any video, replaying a recording through the whole system, connecting a camera, and a whole-video forecast check |

## What it showed

These sentences are safe to repeat. Please do not strengthen them.

- **Count forecast (C1): supported.** On held-out cameras, the ridge model's next-minute error was 0.748
  vehicles, against 0.972 for repeating the last minute. The difference is 0.224, 95% CI 0.181–0.271 (P105).
- **Vision model MFSTNet (C2): not shown to help.** On four foreign cameras, the full model could not be
  told apart from a simple linear probe. With four cameras, the test could only have detected a difference
  of about 0.21 macro-F1.
- **Forecasts for signal control: a null result.** "No demonstrated control benefit from forecasts under
  the tested conditions" (P130).
- **Not yet shown:**
  - results on Indian footage (every evaluation camera is foreign);
  - accuracy against human counts;
  - performance on a live camera.

## See it running

On a computer with the project set up ([Execution Manual Part 0](90-manual/EXECUTION_MANUAL.md#part-0--setup)),
plus Mosquitto and the footage:

```bash
cd dashboard && npm run build && cd ..
python scripts/demo_launcher.py --mosquitto <path to mosquitto.exe> --clips-root <footage folder>
```

Open `http://127.0.0.1:18080/`.
- **Analyze a video:** opens a recording and its results.
- **Live → Run through the system:** replays a clip through the whole deployed system, labelled REPLAY.

Manual §5.5.1 and §5.5.2 explain each step, including how to connect a camera.

## Ground rules

- **Do not add video frames to the repository** (NFR-13). The traffic footage's licence is unresolved. The
  preview images already under `data/lanes*/` are part of the licensing review (S68).
- **"Agreement, not accuracy."** Until S67, no number here is an accuracy figure.
- **Results come from committed result files,** generated by scripts, never typed by hand.
