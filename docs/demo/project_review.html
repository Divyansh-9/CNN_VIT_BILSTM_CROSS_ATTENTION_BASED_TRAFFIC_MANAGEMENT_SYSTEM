The coupling that is easy to miss

MFSTNet's output is not just a prediction — it is part of the PPO state vector. Four per-lane class predictions occupy indices 11–14 of a 16-dimensional state. Change MFSTNet's output shape and every trained PPO checkpoint is invalidated.

Two fallbacks are required behaviour

If MFSTNet inference fails, PPO runs on raw counts with indices 11–14 zeroed — never a shortened vector. If MQTT drops for more than 10 s, the edge node switches to a locally-embedded Webster controller.

0.3500 is the honest deployment number, not 0.8941. A model deployed on a junction it has never seen is in the third column.

Adding 1,254 human-annotated TrafficCAM boxes moved that to 0.5734† and brought e_rickshaw from 0.000 to 0.4787† — the detector had been shipping an output head that had never seen a single example of a class the project exists to handle.

That arm is not adopted: it failed a sixth pre-registered criterion (IDD −0.0916 against a 0.02 tolerance). The criterion was fixed before the run and is not being retuned to fit the number it rejected. Whether dashcam accuracy should still be an acceptance surface is an open decision, made forward.

The expensive pass runs once

The detector pass produces counts.csv and detections.csv. Both are independent of the choices made after them — a threshold change re-derives in seconds, and a lane centre moved by hand re-derives in 0.66 s instead of hours.

Why that matters more than speed

Lane placement is done by eye over a heat map. It was never going to be right first time. A feedback loop costing hours per iteration is one that gets used once — and the placement gets judged on how it looks rather than on the counts it produces.

Decision · A28

A pre-registered statistic, and what it returned

Sampling every 2 s instead of 5 keeps four cameras alive

PRD §8.2 fixes step_s = 5 as a bare number derived nowhere. A28 pre-registered ceil(P75/59) to replace it — chosen before the footage existed and deliberately biased against our preferred answer. Measured across three detectors and two threshold sets, it returns 1 or 2 in all six combinations. Never 5.

step_sClip minimumSequencesIndependent segmentsCameras contributing
5 — current355 s302297 of 11
2 — proposed178 s3596411 of 11
1119 s38110111 of 11

The sequence column is the weaker argument. Overlapping windows inflate any sequence count — the measured inflation is 5.6×.

The column that matters is the last one. step_s = 5 needs 355 s of continuous footage per clip and therefore deletes four cameras outright. Sequences from one camera are correlated; cameras are the unit the model must generalise over, and no augmentation manufactures a viewpoint.

The gate is a research artifact, not an implementation detail. It is logged every run, tracked on the dashboard, and analysed in the paper — so "what value does it take, and why" is a question the report has to answer rather than a diagnostic.

Backbones are frozen and their features cached, which is what makes an eight-config ablation feasible on a 6 GB laptop GPU. Ablation-ability is an architectural constraint: every module can be disabled by a config flag, with no code edit between configs.

Result · the gate

The question we could answer before the corpus exists

The gate can gate — the flat gate is a fact about the data

On the pilot corpus the gate sits at mean 0.54, std 0.005: one value for every location and timestep, which is a scalar blend rather than a gate. Instrumenting its input explains exactly why — z_a and z_b are nearly orthogonal (cosine −0.004) but small, std 0.035, so the sigmoid never leaves its linear region.

SeedGate stdg when CNN carries signalg when ViT carries signalSeparation
10.3200.4040.6700.266

Given a task where half the samples carry the label in the CNN branch and half in the ViT, the gate moves by 50–90× its pilot spread and routes toward whichever branch is worth reading. That is the mechanism doing what it was chosen for.

The caveat, recorded rather than hidden. The fusion returns norm(fused + 0.5·(f_cnn + f_vit)) — the residual adds both branches back ungated, so neither can be suppressed. That bounds how much of the ablation's F→G difference gating can ever account for, and it belongs in the paper rather than in a reviewer's question.

Mean wait in seconds. The headline comparison is made at saturation, where signal timing decides the outcome.

Two disqualifications, applied automatically

In light traffic Webster's cycle formula clamps 100% of the time — that is a fixed-time controller wearing Webster's name, so the comparison is not citable.

Survivorship, caught by rule

In oversaturated traffic all three controllers complete under 85% of trips. A low mean wait there measures only the vehicles that got through, so the whole regime is disqualified.

Two independent faults behind one symptom

The documented install command pointed at a CUDA index that no longer carries PyTorch at any version, so it silently resolved to the CPU wheel. And the training script had no device handling at all — so a correct install would still have run on the CPU with the GPU idle.

Half of every epoch was the wrong dtype

The cache stores fp16 and the model wants fp32. Widening on the CPU meant torch.stack copied and the bus carried twice the bytes. Widening after the transfer is exact — all eight configs agree on every one of 32 recorded fields.

Method

Reproducibility · NFR-07 to NFR-10, graded Critical

The machinery that stops a wrong number from looking right

Pre-registered thresholds

A28's statistic, ADR-012's disqualifications and S17's six criteria were all fixed before the runs that tested them. That rule has cost us the preferred answer four times, which is the only reason it is worth anything.

Results are written, never transcribed

Every table comes from a committed CSV produced by the script that ran the experiment. A short verification run now refuses to overwrite results recorded from a longer one.

The corpus is audited against itself

Nine checks re-derive a corpus from its own more primitive files — including that the label sits exactly 60 s after the last observed frame. All seven deliberate mutations of a good corpus are caught.

Every result carries its environment

Torch version and build, CUDA device, both TF32 flags, package versions, git commit. 2.13.0+cpu and 2.13.0+cu126 are the same version and cannot produce the same numbers.

The honest limit. The corpus is 64 independent segments across 11 cameras, and 20 of those segments come from a single motorway clip. Sliding windows produce 359 training sequences from it, and both numbers travel together in the paper — the window count alone overstates the evidence by 5.6×.
